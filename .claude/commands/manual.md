인자: `$ARGUMENTS` (inbox 아래 폴더명, 형식 `<부서>_<업무명>`)

먼저 `CLAUDE.md`의 작성 규칙과 `templates/manual_template.md`를 읽는다.

## 절차
1. **입력 확인**: `inbox/$ARGUMENTS/`가 없으면 중단하고 안내. 폴더명을 첫 `_` 기준으로 `<부서>`와 `<업무명>`으로 나눈다. `memo.md`와 이미지 목록(png/jpg/jpeg/gif/webp)을 확인. 이미지가 없으면 그 사실을 알리고 메모만으로 진행할지 사용자에게 묻는다.
2. **이미지 판독**: 모든 이미지를 Read로 직접 열어 화면 종류(ERP 메뉴, 엑셀 시트 등), 메뉴 경로, 버튼·입력란 위치, 컬럼명, 값 형식을 파악한다. 파일명 순서 또는 memo.md의 언급 순서로 단계 순서를 정한다.
3. **민감정보 점검**: 개인정보, 거래처 단가, 계좌 등이 보이면 본문에 옮기지 말고(`[민감정보 - 생략]`), 이미지·항목을 사용자에게 알린다. 해당 이미지는 이동하지 않고 inbox에 남긴 뒤 가림 처리 여부를 묻는다.
4. **매뉴얼 작성**: 템플릿의 11개 장을 모두 채워 `manuals/<부서>/<업무명>.md` 생성.
   - 메모·이미지에 근거가 있는 내용만 쓴다. 근거 없는 내용은 쓰지 않고 11장에 질문으로 남긴다. 합리적 추론은 `(추정)` 표시.
   - 업무 용어는 첫 등장 시 한 줄 설명. 화면 위치는 구체적으로.
   - 3장 Mermaid는 문법 오류가 없게 작성. 8~10장은 메모에서 드러난 수작업 포인트를 근거로 작성하고 난이도를 상/중/하로 표시.
5. **이미지 이동**: 민감정보가 없는 이미지를 `manuals/<부서>/images/`로 옮기며 `<업무명>_01.png`, `_02` … 형식으로 개명(단계 순서, 원본 확장자 유지). 본문의 이미지 링크(`images/...`)와 일치시킨다. `mkdir -p`로 폴더 생성, `git mv`가 아닌 `mv` 사용.
6. **INDEX 갱신**: `manuals/INDEX.md`(없으면 생성)에 부서별로 `| 업무명 | 주기 | 담당 | 상태 | 확인 필요 건수 | 링크 |` 표를 유지. 이미 있는 업무는 행을 갱신, 없으면 추가. 부서·업무 가나다순.
7. **보고**: 생성 파일, 이동한 이미지, 민감정보 발견 여부, 확인 필요 질문 목록을 사용자에게 요약.
